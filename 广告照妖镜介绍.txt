              广 告 照 妖 镜 （v1.0.0）
                 照一照，广告现原形
═══════════════════════════════════════════════════════════════

一款免费的 Chrome 浏览器扩展。它用 Jev 大模型实时识别网页里
的硬广、软广、引流帖、水军评论和 AI 生成内容，在内容旁边亮出
「照妖徽标」，还能一键把广告折叠、模糊、盖住收走。内置微博、
小红书、知乎、淘宝/天猫、京东五大阵地；其它任何网站，手写几条
CSS 规则就能挂上去照。


─────────────────────────────────────────────
一、安装与开光（三步）
─────────────────────────────────────────────

1. 装扩展
   Chrome 地址栏输入 chrome://extensions 回车 → 打开右上角
   「开发者模式」→「加载已解压的扩展程序」→ 选中扩展文件夹。

2. 领 key
   点浏览器右上角的照妖镜图标 → 切到「key设置」页 → 点
   「哪里领 key」跳转 Jev 官网（docs.typesafe.ai），注册领一个。

3. 开光
   把 key 贴进镜心，点「开光」。扩展会拿一句测试广告语现场验
   key，成功后提示「识破把握 xx%」。key 只保存在你自己这台电脑
   里，不给任何人。

   高级：默认直连官方接口 https://api.typesafe.ai/v1/systemone，
   在「换一条路 · 接口地址可自定义」里可以填中转地址（首次会请
   求域名授权，同意即可）。


─────────────────────────────────────────────
二、内置照妖阵地
─────────────────────────────────────────────

【社媒】（弹窗「社媒」页，三个开关独立控制，不勾的站页面完全不动）

  照微博    —— weibo.com 新版信息流、s.weibo.com 搜索结果、
               m.weibo.cn 移动版
  照小红书  —— 笔记详情页、首页瀑布流卡片
  照知乎    —— 问题页回答、首页推荐流、搜索结果、专栏文章

【电商】（弹窗「电商」页，与社媒开关互不干扰）

  照淘宝/天猫 —— 商品详情页评论、「查看全部评价」整页列表
  照京东     —— item.jd.com 商品页评价区、product.jd.com 整页评价

  电商场景的徽标文案单独特化：不叫「软广」，叫「疑似刷评」——
  好评返现来的、刷单水军写的、AI 批量生成的评论，名字旁边直接
  亮牌（真实评论也会亮「真实评论」牌，一眼对比）。

被照出的内容会按类型亮牌：

  硬广    明晃晃卖货的
  软广    装成分享、实则带货的
  引流    「私信我」「看主页」往站外勾人的
  非广告  干净内容（电商场景显示「真实评论」）


─────────────────────────────────────────────
三、照妖的玩法
─────────────────────────────────────────────

1. 亮牌 / 收走（社媒页「照到之后」）
   亮牌照妖：只在内容旁挂徽标，页面照旧。
   直接收走：判成广告的内容当场折叠/模糊，点徽标可放出来。

2. 三档照妖火力（防误伤/宁可错杀自己选）
   文火（0.8）：只抓高把握的，几乎不误伤。
   武火（0.6）：常规火力。
   三昧真火（0.4）：火越旺，越多疑似广告藏不住。

3. 见词就收（最多挂 30 个词）
   挂上「瘦身」「招代理」这类词，内容撞词直接收走，不必等 AI。
   开「按意思收」后还能抓变体：挂「医美」，连「热玛吉变美体验
   官」也一起照出来。

4. 验 AI 成色
   机器批量写的稿子，徽标上盖「AI xx%」小印（50% 以上直接印
   在牌上，40% 以上悬停可见详情）。「AI 批量好评」是电商刷评的
   主力形态之一。

5. 给作者记账 + 小黑屋
   谁三天两头发广告，照几面就记住：作者档案显示「x 条里 y 条
   是广告」。惯犯可以在战报里或「小黑屋」页一键「关起来」——关
   进去的人，内容直接收走，不再过镜、不费 key。

6. 照妖日报（弹窗默认首页）
   今日照了几条、几条现形、几条收走、广告浓度百分比，硬广/软广
   /引流的细账，惯犯排行榜。点「抄走战报」复制一段可分享的
   「照妖簿」文案。


─────────────────────────────────────────────
四、自定义网站规则填写教程（重点）
─────────────────────────────────────────────

弹窗「自定义网站」页里有两种规则，互不相干，按需各挂各的：

  ◆ 广告标识 —— 内容送到 Jev 照妖，可能亮牌、可能收走，费 key
  ◆ 屏蔽列表 —— 纯本地关键词匹配，撞词直接处理，不走 AI、
                 不亮牌、不费 key


【第一步：学会找 CSS 选择器（F12 手把手）】

挂规则唯一要写的「代码」就是 CSS 选择器（告诉镜子东西在页面
的哪个位置）。以 IT之家首页列表为例：

  1. 打开目标网站，按 F12 打开开发者工具。
  2. 点元素面板左上角的「箭头+方框」图标（或按 Ctrl+Shift+C），
     进入选取模式。
  3. 鼠标移到一条新闻上，页面里出现蓝色高亮框，同时元素面板里
     高亮对应节点——这个节点就是「一条内容」。
  4. 找「正好包住整条内容」的最外层：选小了会丢标题或作者，
     选大了会一次框住好几条（全页只判成一张卡）。
  5. 右键高亮节点 → Copy → Copy selector。
  6. 警告：Chrome 复制出来经常长这样——
        #list > div.fl > ul > li:nth-child(2)
     其中 nth-child(2) 意思是「第 2 条」，只有第 2 条能匹配上，
     换一页、刷新一下就失效。要手工改成共性写法：
        #list > div.fl > ul > li          （去掉 :nth-child(2)）
        —— 或者更干脆的 ul.nl li
  7. 验证：切到 Console 标签，粘贴回车——
        document.querySelectorAll("ul.nl li")
     列表页应返回几十个元素的 NodeList。返回 0 是选择器写错了；
     只返回 1 很可能就是 nth-child 路径问题。

标题、正文、作者这些选择器也是同样找法，只是它们是「条目里面」
的元素，比如 IT之家一条新闻里的 <a> 就是标题。


【第二步：「广告标识」规则，逐字段填写说明】

必填三项打 * 号：

  站点域名 *    填 ithome.com 或 *.ithome.com（两种写法都包含
                全部子域名）；直接粘整段网址也行，会自动剥掉协议
                和路径。注意：写 www.ithome.com 则只精确匹配这
                一个子域。
  备注名        给自己看的，如「IT之家 · 列表」。
  内容条目 *    一条内容的最外层选择器，如 ul.nl li。
  标题选择器    条目里的标题，如 a。标题/正文至少填一个，镜子才
                知道照什么文字。
  正文选择器    条目里的正文块，如 #paragraph。
  作者选择器    条目里的作者名。留空当无名氏（不影响判广告，只
                是没法记作者档案）。
  照到广告后    下拉四选一：
                  只亮牌     默认，仅挂徽标
                  模糊内容   判中后内容变模糊，点徽标放出来
                  折成一行   判中后整个收成一行（适合列表流）
                  盖住内容   用提示层整个盖住

  高级（不确定就留默认）：

  身份指纹      一个条目的「身份证」。填了它，条目没换就不重新
                照（省 key）；内容换了指纹跟着变，自动重判。
                写法是「选择器@属性」：
                  a@href    取条目里第一个 <a> 的 href（列表页
                            推荐这个，一链一条）
                  h1        取条目里 h1 的文字（文章详情页推荐）
                  @id       取条目自身的 id
  链接选择器    条目里的链接 <a>，给镜子作参考。
  徽标挂点      徽标具体挂在哪个元素旁边。留空 = 挂在条目身上。
  挂法          「跟在挂点后面」是默认（行内排开）；「浮在挂点
                里面」适合瀑布流这类高度固定的卡片，浮动提示层
                不改变卡片排版。
  收走时遮住    「模糊/盖住」时具体动哪一块，如 #paragraph。
                留空自动处理。
  提示浮层放    悬停徽标时提示层的位置：填 self 浮在整条内容
                上，或填任意选择器。默认自动。

  填完点「挂上」。保存前扩展会逐个校验：标题/正文至少填一个、
  每个选择器都必须是合法 CSS，不合规矩当场打回，不会等到网页上
  才发现没生效。保存后把那个网站刷新一遍就开照。

  想快，先点表单下方的示范按钮「示范 · IT之家列表」或
  「示范 · IT之家文章页」，表单自动填好，照着改就行。


【第三步：抄两个现成的（IT之家实战样例）】

  ◇ 列表页规则（点「示范 · IT之家列表」自动填入）：
      站点域名     ithome.com
      备注名       IT之家 · 首页列表
      内容条目     ul.nl li
      标题选择器   a
      链接选择器   a
      身份指纹     a@href
      徽标挂点     a
      照到广告后   折成一行
    含义：IT之家每条新闻是一张卡；一链一条指纹；软广判中就整
    条折成一行，点徽标展开。

  ◇ 文章页规则（点「示范 · IT之家文章页」自动填入）：
      站点域名     ithome.com
      备注名       IT之家 · 文章页
      内容条目     #dt .fl.content
      作者选择器   #author_baidu strong
      标题选择器   h1
      正文选择器   #paragraph
      身份指纹     h1
      徽标挂点     .info .l
      收走时遮住   #paragraph
      提示浮层放   self
      照到广告后   模糊内容
    含义：详情页只照一篇文章本身；标题当指纹（换文章自动重判）
    ；判中软文只模糊正文段落，标题和评论区不受影响。

  换别的网站时思路一样：列表流 → 条目+标题+a@href+折成一行；
  详情页 → 大容器+h1 指纹+模糊正文。


【第四步：「屏蔽列表」规则（不费 key 的纯关键词屏法）】

适合「这站的某些话题我根本不想看见」：撞到词的文章条目直接处
理，不过 AI、不亮牌。

  站点域名 *      同上。
  备注名          如「IT之家 · 屏蔽列表」。
  文章条目 *      列表里一条文章的最外层，如 ul.nl li。
  取文字处        撞词看哪段文字，如 a（只看标题）。留空用整条。
  撞到关键词后    三选一：
                    直接隐藏     条目原地消失
                    模糊看不清   变马赛克
                    淡成灰色     弱化到不起眼
  屏蔽关键词 *    一行一个，或用 、 / ， / ; 隔开。上限 50 个。

  对应示范按钮：「示范 · IT之家列表」（item=ul.nl li, text=a,
  style=直接隐藏）。加词、改词后刷新网站即生效。


【挂规则常见问题】

  Q：挂上了但不亮牌？
  A：① 那个网站刷新了吗？规则存好后须刷新才生效。
     ② F12 看 Console，有「[照妖镜] 脚本已注入」「[照妖镜] 生效
        规则 x」两行日志：前者没有 = 页面没注入；后者数量为 0 =
        域名没匹配上（检查「站点域名」写法）。
     ③ key 开光了吗？没 key 时广告标识规则不出效果。

  Q：整个列表全被判成广告？
  A：多半是「内容条目」选大了，一次把整页装进一张卡。用第一步
     的 Console 验证法，确认选择器返回的是几十条而不是 1 条。

  Q：徽标位置不对/挤坏排版？
  A：调「徽标挂点」和「挂法」——瀑布流卡片用「浮在挂点里面」。

  Q：规则怎么改、怎么删？
  A：「已挂的规矩」列表里每条规则右边有「改」「摘」两个按钮。


─────────────────────────────────────────────
五、隐私、缓存与花费
─────────────────────────────────────────────

  · key 只存在你本机浏览器里，不会上传给任何人。
  · 文案内容会发送到你在「key设置」里填的接口（默认 Jev 官方）
    做判定；除此之外扩展不收集任何数据，无账号、无埋点。
  · 判定结果本地缓存：同一段内容不重复请求、不重复计费；列表
    滚动加载、React 整卡重挂时靠「身份指纹」免于重复照。
  · 不勾的平台、没挂规则的网站，脚本完全静默，页面零改动。

七、发布到 GitHub 开源（手把手教学）
─────────────────────────────────────────────

想把自己的照妖镜开源给全世界用？跟着走，全程约十分钟。
Windows 命令为准（PowerShell / 终端通用），Mac 把路径换成
自己的即可。

【第 0 步：备好两样工具】

  ① 装 Git
     打开 PowerShell 输入：
         git --version
     显示版本号（如 git version 2.xx.x）就是已装过，跳过。
     显示「无法识别」则去 https://git-scm.com/downloads 下载
     Windows 版，安装全部默认、一路下一步即可。

  ② 注册 GitHub 账号
     浏览器打开 https://github.com → Sign up → 填邮箱、
     密码、用户名（英文，全网唯一，以后就是你的开源署名）。


【第 1 步：开源三件套（少一件都不像正经开源）】

  在扩展目录 c:\Users\Bug11\Desktop\ad\zhaoyaojing\ 里，用
  记事本新建三个纯文本文件（.gitignore 注意没有文件名、
  只有扩展名，保存时文件类型选「所有文件」）：

  ① README.md —— 仓库门面，别人点进来第一眼看到的页面。
     建议四段：
       - 是什么：一两句话（可直接抄本介绍开头那段）
       - 怎么装：chrome://extensions → 开发者模式 →
         加载已解压的扩展程序（可参考第一章）
       - 怎么配 key：docs.typesafe.ai 领 key 填入弹窗
         （可参考第一章第 2、3 步）
       - 免责声明：把第六章整段复制进去

  ② LICENSE —— 法律许可，决定别人能拿你的代码干什么。
     推荐选 MIT（最宽松：任何人可随意用、改、商用，只要保
     留你的版权声明）。去 https://choosealicense.com 页面
     复制 MIT 全文，存成 LICENSE 文件（无扩展名），把里面
     的 <year> 改成 2026、<fullname> 改成你的 GitHub 用户
     名即可。
     不想选 MIT也可以在那网站比较 Apache-2.0 / GPL-3.0 等，
     但新手直接 MIT，几乎不会错。

  ③ .gitignore —— 告诉 Git「这些垃圾别上传」。内容只需
     三行：
         Thumbs.db
         Desktop.ini
         .DS_Store
     （分别是 Windows 缩略图缓存、文件夹配置、Mac 垃圾文件）

  顺手把本介绍文章也复制一份进扩展目录，README 里写一句
  「完整介绍见 广告照妖镜介绍.txt」，随仓库一起发布。

  https://github.com/你的用户名/ad-zhaoyaojing.git 的地
  址，复制留用。


【第 3 步：本地推送（核心五条命令）】

  PowerShell 里依顺序整段执行（把「你的用户名」换成自己
  的；第一条 cd 后面就是扩展文件夹路径）：

     cd c:\Users\Bug11\Desktop\ad\zhaoyaojing
     git init
     git add .
     git commit -m "first commit: 广告照妖镜 v1.0.0"
     git branch -M main
     git remote add origin https://github.com/你的用户名/ad-zhaoyaojing.git
     git push -u origin main

  各条的意思：
     git init            把这个文件夹变成 Git 仓库
     git add .           把全部文件纳入待提交
     git commit -m "…"   打包存一版，引号里是说明
     git branch -M main  主分支统一叫 main（GitHub 现行约定）
     git remote add …    记住远程仓库地址
     git push -u origin main  本地→GitHub 首次上传

  首次 push 会弹出 GitHub 登录窗口（浏览器授权点一下绿
  色Authorize 即可）。之后 push 不再要求登录。

  推送成功的标志：刷新 GitHub 仓库页面，能看到全部文件，
  README 内容直接显示出来。


【第 4 步：发第一个正式版 Release】

  版本库页面右侧 Releases → Create a new release：

    Tag version     v1.0.0（和 manifest.json 里的版本号
                    保持一致，日后每发一版同步涨）
    Release title   广告照妖镜 v1.0.0
    Describe        一段更新说明（可摘自第五章/第一章）

  点 Publish release。别人就能从这个页面追踪每次更新。


【第 5 步：日后改了代码怎么更新（三连）】

 以后每次改完代码，在扩展目录执行三连：

     git add .
     git commit -m "这次改了什么的一句话说明"
     git push

  发新版（例如 v1.1.0）额外两步：
     ① 把 manifest.json 和文章里的版本号改成 1.1.0，
        三连推上去；
     ② GitHub 页面 Releases → Draft a new release，
        Tag 填 v1.1.0，发布。


【开源前最后一次安全自检】

  push 之前，确认仓库里没有这四类东西：

    ① 硬编码密钥 —— 本扩展的 key 是用户自己填的、不存在
       于代码里，天然安全；但仍建议全局搜一遍 sk- 、
       api_key = 、token =，确保无漏网之鱼。
    ② 个人隐私 —— 截图里的昵称头像、真实姓名邮箱、报销
       记录类的文件，一律不进仓库。
    ③ 无关文件 —— 临时测试脚本、报废草稿，删干净再 add。
    ④ 版权素材 —— 图标若来自网络，确认许可允许商用再公
       开；拿不准就换自己画的。


【常见问题】

  Q：push 报 401 / Authentication failed？
  A：凭据过期。Windows「凭据管理器」→ Windows 凭据 → 删
     掉 git:https://github.com 那条，再 push 重新登录。
     或者用 Personal Access Token：GitHub → Settings →
     Developer settings → Personal access tokens → 生
     成一个，push 密码处粘贴它。

  Q：手滑把敏感文件推上去了，怎么撤？
  A：若只是最后一次提交，执行
         git rm --cached 文件名
         git commit -m "remove xxx"
         git push
     若已推了很久才发现，仅删除不够（历史里还在），需要
     改写历史，届时再单独处理。

  Q：想上传又怕以后不维护？
  A：README 里写一句「随缘维护」即可。开源不等于打工，
     第六章第 5 条已经替你把话说明白了。

  Q：要不要同时发布到 Chrome 商店？
  A：GitHub 开源（免费、面向开发者）和 Chrome Web Store
     上架（$5 开发者注册费、面向普通用户）是两回事，可
     只发 GitHub，互不影响。

八、项目介绍页（GitHub Pages 主页教学）
─────────────────────────────────────────────

仓库里光有代码还不够气派——再给它配一个能在浏览器直
接打开的「门面主页」，白送一个二级网站，全程免费。扩展
目录里已经建好页面文件：

    zhaoyaojing\docs\index.html

（墨底铜镜配色，含照妖现场演示、亮点、安装步骤、自定义
规则示意和 FAQ，双击可直接本地预览）。

GitHub 每个仓库自带一项免费托管服务：GitHub Pages。
开启后它会变成一个网址：

    https://你的用户名.github.io/ad-zhaoyaojing/

把这个链接写进 README 开头，或直接发给朋友——对方看得
见页面，看不见代码，这就是「作为主页介绍这个插件」。


【第一步：改一处用户名】

  用记事本打开 docs\index.html，全文搜索 yourname，
  替换成你的 GitHub 用户名（共 5 处 GitHub 链接，含页脚
  Releases 那条），保存。
  页面顶部注释里写了同样提示，改完可顺手删掉那几行注释。

  记事本操作：Ctrl+H → 查找 yourname → 替换为 你的
  用户名 → 全部替换。


【第二步：推上 GitHub】

  第七章教过的三连，在本仓库目录照常执行：

     git add .
     git commit -m "add project homepage"
     git push

  （首次上传还没建仓库的，先回去补第七章第 2、3 步。）


【第三步：开启 Pages（一次性设置）】

  打开你的仓库页面：

    Settings（仓库的，不是头像里的）→ 左侧 Pages
    → Build and deployment
        Source      选 Deploy from a branch

【第四步：等一分钟，开主页】

  会给出访问地址。等 1～5 分钟（右上角 Actions 转圈结
  束），浏览器打开：

    https://你的用户名.github.io/ad-zhaoyaojing/

  看到「广告照妖镜 · 照一照，广告现原形」墨色页面即成。

  建议顺手把这个地址贴进 README.md 第一行、GitHub 仓库
  Description、以及发布到贴吧/论坛时的正文里。


【日后改版怎么更新】

  介绍页跟代码一样走三连：改 docs\index.html →

     git add .
     git commit -m "update homepage"
     git push

  推完 1～5 分钟自动重新构建，无需再动 Settings。


【Pages 常见问题】

  Q：打开是 404？
  A：按顺序查——
     ① 地址打对了吗？是 github.io 不是 github.com；
     ② Branch/文件夹选的是 main + /docs 吗？选成
        /(root) 或 /docs 之外的都会 404；
     ③ 等 Actions 构建完了吗？仓库上方 Actions 标签
        里转黄圈=构建中，绿勾=成功，红叉=构建失败
        （点进去看日志，通常为 HTML 语法问题）；
     ④ 仓库是 Public 吗？免费版 Private 仓库的 Pages
        不可用，去 Settings→General 改 Visibility。

  Q：访问太慢 / 打不开（国内网络）？
  A：github.io 在部分网络环境不稳定属正常，仓库本身
     不受影响。介意速度可再绑自己的域名（见下一条）。

  Q：能用我自己的域名吗？
  A：能。域名商处加一条 CNAME 记录指向 你的用户名
     .github.io，再在仓库 Settings → Pages → Custom
     domain 填入。没有域名就先用送的二级网址。

  Q：想要 你的用户名.github.io 这种顶级主页？
  A：那是另一个专属仓库：新建名为 你的用户名
     .github.io 的仓库（名字必须一字不差），把 docs\
     index.html 放到它根目录，Pages 什么都不用设开箱
     即用。它通常放个人总主页，介绍单个插件建议还是
     用本仓库的 /docs，两不相误。

  Q：主页和扩展里的文件会互相干扰吗？
  A：不会。docs 文件夹不参与扩展运行（Chrome 只认
     manifest.json），也不影响第七章的发布流程。
